# 任务书：用 shader-art-coding 技能复刻参考视频

## 目标

把 `assets/reference.mp4` 的画面复刻成**一个 Shadertoy GLSL 文件**。不是逐像素还原 3D 游戏，而是用程序化
着色器做出同一个场景、同一套配色和同一段运镜。

## 输入

| 文件 | 说明 |
|---|---|
| `assets/reference.mp4` | 1920×1080、24 fps、338 帧；首帧 pts 0.083 s，末帧 pts 14.125 s。两个镜头，时间轴见下 |
| `assets/ref-t2.0.png` | 镜头 A 参考帧（pts 2.0），960×540 |
| `assets/ref-t6.0.png` | 镜头 B 广角参考帧（pts 6.0），960×540 |
| `assets/ref-t12.0.png` | 镜头 B 近景参考帧（pts 12.0），960×540 |
| `assets/contact-sheet.png` | 每秒一帧的总览 |
| `.claude/skills/shader-art-coding/` | 技能本体：186 个已验证 GLSL 函数、bundler、checker、模板与参考文档 |

## 参考时间轴（实测，时间均为视频 pts）

| 时段 | 镜头 | 运镜 |
|---|---|---|
| 0 – 3.583 s | A：码头 | 斜俯视，镜头跟着船往上游摇，画面整体向下滚动；水面占比从 0.34 降到 0.11 |
| 3.625 s | 硬切 | 第一帧 B 出现在 pts 3.625 s，即第 85 帧（从 0 起数）；帧差 0.204，其他时刻都 ≤ 0.10 |
| 3.625 – 6.8 s | B：瀑布湾广角 | 缓慢下降并推近 |
| 6.8 – 7.4 s | B | 快速推近到近景 |
| 7.5 – 14.125 s | B：近景 | 基本静止，只有鱼、钓线和水面在动 |

## 交付

| 文件 | 要求 |
|---|---|
| `work.glsl` | 源码，按名字调用库函数 |
| `final.glsl` | `glsl_tools.py bundle work.glsl -o final.glsl` 的输出；粘贴即用，只含 `mainImage`，无 `#version`、无贴图、无自定义 uniform |
| `verify/t2.png` `verify/t6.png` `verify/t12.png` | 用 `final.glsl` 在 iTime = 2.0 / 6.0 / 12.0 渲染的截图，16:9 |
| `verify/render.mp4` | 用 `final.glsl` 渲染的整段视频：24 fps，pts 从 0 开始，pts 为 t 的帧用 iTime = t 渲染，至少覆盖到 14.125 s |
| `NOTES.md` | 用了哪些库函数；哪些还原了、哪些没还原；`score.py` 的完整输出；超线指标的处理；两份视觉评审结论 |

## 约束

- 单文件，最终用技能自带工具打包：`glsl_tools.py bundle`
- 必须调用技能库里的函数，不要另抄一份
- 时间轴按上面的实测复刻：A 段摇镜，3.625 s 硬切，B 段缓推 → 快推 → 静止
- 不画游戏 HUD（左上时间、上方 Creel 计数、左下按钮、右上弹窗、底部进度条）
- 16:9；所有坐标以画面高度为 2 个单位

## 验收标准

分三层。程序检查只能证明"没犯硬错"和"统计上接近"，是不是同一个场景、同一段运镜，最终由视觉评审判断。

### 第一层：硬性要求（`score.py` 判定，任一失败即不通过）

| 项 | 内容 |
|---|---|
| H1 | `final.glsl` 与 `bundle(work.glsl)` 一致；至少调用一个库函数；`work.glsl` 不重定义任何库函数；无 `#version` / `iChannel` / `uniform`；`glsl_tools.py check final.glsl` 通过 |
| H2 | 三张截图和 `render.mp4` 都在；`render.mp4` 为 24 fps，覆盖 0 – 14.125 s |
| H3 | 硬切：`render.mp4` 里帧差最大的位置就是硬切，它后面第一帧的 pts 与参考相差不超过 1 帧（3.583 – 3.667 s）。开头黑帧之类的闪帧也会让这一项失败 |

### 第二层：参考指标（`score.py` 报告，不单独决定通过与否）

所有指标都在 320×180 下计算，并且在参考和本作两边同时遮掉 HUD 区域。

| 项 | 指标 | 参考线 |
|---|---|---|
| Q1 | 9 个色块平均色的 ΔE76（CIE Lab），色块见下表 | ≤ 10 |
| Q2 | 六类（水/岩/木/植被/沙/暗部）面积占比之差 | ≤ 0.08 |
| Q3 | 平均亮度差 | ≤ 0.08 |
| Q4 | 亮度标准差差 | ≤ 0.06 |
| Q5 | 细节密度比（平均梯度，本作 ÷ 参考） | 0.6 – 1.8 |
| T1 | 时间轴：每 0.25 s 一个采样点（共 57 个），水面占比之差 | 每点 ≤ 0.08 |
| T2 | 时间轴：同上，平均亮度之差 | 每点 ≤ 0.08 |
| L | 布局一致率：画面分成 32×18 格，每格平均色按六类分类，与参考同类的格子占比 | 只报告数值，由视觉评审判断 |

布局一致率的参照（在参考视频自身上实测）：完全不同的场景约 0.25；同一镜头机位相差 1 s 约 0.65；只在色块位置涂色的假画面 0.14 – 0.49。

超出参考线的每一项，都要在 `NOTES.md` 里写明：已修复，或在视觉评审里说明为什么可以接受。

### 第三层：视觉评审（最终判定）

**评审材料**（`score.py` 自动生成）：

- `verify/review/sheet.png`：参考（左）与本作（右）在 1, 2, 3.5, 3.75, 5, 6, 7, 7.5, 10, 12 s 的并排图
- `verify/review/side_by_side.mp4`：整段左右并排视频，用来看运镜节奏

**评审人**：两份评审都通过才算通过。

1. 制作者自查，按下面的清单逐项看，不通过就继续迭代。
2. 独立评审：一个没参与制作的 clean-context subagent。它只拿到评审材料、本清单和 `score.py` 输出，不看对话和源码。

**清单**：每项判三点——在不在、位置对不对（落在参考画面的同一区域）、颜色对不对。

| 镜头 | 主体元素（缺一项即不通过） | 次要元素（缺失要在 NOTES.md 说明） |
|---|---|---|
| A | 木屋（含屋顶）、码头平台、河道、右侧沙岸、船 | 栈桥、树、石头、草地 |
| B 广角 | 岩壁环、水湾、顶部瀑布、船、两侧树林 | 大石块、鱼群 |
| B 近景 | 岩壁、水湾、瀑布、船和钓客 | 钓线、浮标、鱼群 |
| 全程 | 水按深度变色；阴影大而软 | — |

**运镜**：A 段画面向下滚动的方向与节奏；3.625 s 硬切；B 段先缓推，6.8 – 7.4 s 快推，之后静止。

**整体判断**：一句话结论——不看说明的人能否认出是同一个场景、同一段运镜。

**通过条件**：第一层全部通过；两份视觉评审的主体元素、运镜、整体判断都通过；第二层超线项都已修复或有说明。

## 自检

```bash
# 编译检查（本机已装 glslangValidator 16.6.0）
python3 .claude/skills/shader-art-coding/scripts/glsl_tools.py check final.glsl

# 打包
python3 .claude/skills/shader-art-coding/scripts/glsl_tools.py bundle work.glsl -o final.glsl

# 验收：打印 H1–H3、Q1–Q5、T1/T2、L，并生成 verify/review/
python3 tools/score.py --own-dir verify
```

渲染工具没有强制要求：Shadertoy 网页、无头 Chrome、本机任意 WebGL 环境都可以。三张截图、`render.mp4` 和
`final.glsl` 必须对得上同一份代码。`score.py` 会报告截图与视频同一时刻帧的差异，供评审核对。

`score.py` 的退出码只反映第一层（硬性要求）。最终结论以视觉评审为准。

## 参考事实（客观信息，不是解法）

- 参考是斜俯视的 3D 游戏画面，带手绘材质；阴影大而软，水按深度变色
- 镜头 A：木屋、码头、河道、右侧沙岸、栈桥、树
- 镜头 B：岩壁围出的水湾、顶部瀑布、船与钓客、浮标、鱼群
- 广角（t=6）比近景（t=12）的水色更暗更灰：`#439E83` vs `#33C69C`
- 遮掉 HUD 后的平均亮度：t=2 约 0.56，t=6 约 0.46，t=12 约 0.49
